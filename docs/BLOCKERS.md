# External blockers and validation gates

Recorded on 11 October 2026. These gates remain open; the software does not represent them as passing. Independent setup, implementation, tests, and publication continued after each.

| Gate | Evidence / blocker | Implemented behaviour | Required next step |
| --- | --- | --- | --- |
| Actual Samsung | No physical Samsung is attached. `adb devices` exposes the locally created Android emulator only. | Device-owner status and policy adapters inspect real native state. Emulator enrolment is proven separately. | Attach the intended Galaxy A55 or record the actual model, Android, One UI, patch, and Knox versions; run the full device matrix. |
| Knox SDK and licence | No Knox developer portal identity, SDK jar, or suitable development/production licence was supplied. | Optional proprietary jar integration, activation UI, callback handling, installation-list reconciliation, wildcard/exception checks, and native readback. Unsupported or unauthorized calls fail. | Download the SDK using your Samsung account, obtain suitable licence access, activate on the exact signed APK, prove Play/Galaxy Store/sideload blocks and permitted updates. Confirm licence expiry/renewal behaviour. |
| Resend | No sending API key, verified domain, or webhook secret was supplied. | Official component queue, verified webhook handler, delivery/bounce status, redacted errors, retention cleanup, failed-delivery UI. HTTP test confirmed missing email configuration never grants approval. | Verify a domain, set server-only credentials, prove a test email, then configure real guardian delivery. |
| Real guardians | No two independently owned guardian inboxes were supplied. | Initial primary authorization plus recovery inbox verification; new-inbox verification and current-primary approval for normal replacement; narrow backup recovery route. | Pair deliberately with the two actual addresses and complete both initial challenges. Do not use a user's own inbox as a guardian in daily use. |
| Category source selection | Coverage, maintenance, redistribution terms, and actual Chrome behaviour cannot be accepted without the category prototype. No arbitrary external feed is silently presented as approved. | Four category draft toggles, HTTPS source/licence editing, strict domain-list parser, checksums, bounded downloads, last-known-good cache, maintenance refresh. Submission requires a source for each enabled category. | Select and verify maintained feeds covering social, streaming, gambling, and adult categories; record licence/version/source. Primary guardian approves sources and category choices. |
| Large-category filtering | Chrome managed `URLBlocklist` has a 1,000-entry limit. A Chrome-only forwarding VPN has not been proven and is not included as a fake working engine. | Native managed policy supports full lists up to 1,000 distinct domains. Larger lists fail before applying Chrome changes and report the effective count. No truncated lists or inert VPN interfaces. | Prototype a real per-app forwarding filter or suitable tested filtering service. Test encrypted DNS, Private DNS, IPv6, QUIC, caching, Incognito/Custom Tabs, reboot, network switches, and VPN conflicts while essential apps remain online. |
| Production enrolment | Fresh-emulator ADB enrolment passed, but Google DPC eligibility and the real Samsung enrolment route remain unknown. | Android 12+ provisioning-mode/compliance activities; ordinary UI works without management. | Establish a supported route for this exact release-signed controller and phone. Do not treat a work profile, accessibility app, or emulator success as whole-device management. |
| Full approved removal | Android deprecates `clearDeviceOwnerApp`; no exact Samsung cleanup/release experiment has been performed. | Standalone primary-approved signed removal; tracked cleanup and native checks; build-time validation gate defaults false; no automatic factory reset. | Demonstrate complete cleanup and interrupted recovery on a spare Samsung. Implement a supported release route if the evaluated API is unsuitable. Any reset requires a separate explicit decision. |
| Final bypass protection | Turning off ADB during development would obstruct testing; update/removal proof is pending. | Controller uninstall/user-control protection, explicit final user/debugging restrictions, essential package safety baseline, no blanket app-install ban, no kiosk. Release reports incomplete application while validation is false. | Validate signed controller updates and removal first, then test and explicitly set `CURATED_BYPASS_PROTECTION_VALIDATED=true` for the reviewed release. |
| Banking / Android Auto | No phone, accounts, SIM, car, or banking test context is available. | Essential packages are protected, stock Google services are retained, USB data and non-Chrome networks are not blanket-disabled. | Verify Belfius/itsme registration and app-to-app auth, WhatsApp call/push, navigation location/audio, and the actual wired/wireless Android Auto connection. No real transfer is needed for testing. |
| Everyday installation | Backup, firmware eligibility, Knox licence, email delivery, filtering, and release-route gates remain open. | A signed prototype can be produced with a private stable signing key and separate production backend; it cannot claim daily-use acceptance. | Complete the recorded matrix, privately back up signing keys and phone data, and only then enrol the daily-use phone. |

Credential-free implementation, build checks, emulator testing, hosted Convex deployment, secret generation, release signing preparation, and public repository publication are not blocked. The missing items above require account input or physical-device evidence; elapsed time cannot supply that evidence.
